# TRUTH MAP: EasyUI Settings & State

This document maps the flow of settings from user interaction to persistence and rendering, based on an initial codebase review.

| Setting / Feature              | Written By                                       | Stored In                                                                                              | Read By                                                                 | Rendered In                                                                    | Bug Risk                                                                                                                                                                                                                                                                  |
| ------------------------------ | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `selectedTheme`                | `GuidedSetupViewModel`, `CaregiverViewModel`     | `DataStore`: `SKIN_VISUAL_THEME` key in `launcher_settings.preferences_pb`                               | `AppViewModel` -> `EasyUiNavGraph`                                        | Entire App via `EasyUiTheme`                                                   | **High**. Two ViewModels write to the same `DataStore` key. The UI reads from a third (`AppViewModel`). Lifecycle or race conditions could cause the theme to revert if state isn't synchronized perfectly. This aligns with bug #4.                                                |
| `fontScale/fontSize`           | `GuidedSetupViewModel`, `CaregiverViewModel`     | `DataStore`: `SKIN_READABILITY_PRESET`, `SKIN_FONT_SCALE_FACTOR`, `SKIN_FONT_SIZE_MODE` keys              | `HomeViewModel`, `SeniorHomeTokens`                                       | `HomeScreen` (senior-facing text)                                              | **High**. Onboarding uses "Readability Preset" while Caregiver settings might have different controls. Multiple keys (`fontScale`, `fontSizeMode`) suggest complex, potentially conflicting logic. This aligns with bug #7.                                                   |
| `layoutMode/gridMode`          | `GuidedSetupViewModel`, `CaregiverViewModel`     | `DataStore`: `SKIN_LAYOUT_MODE` key                                                                    | `HomeViewModel` -> `HomeLayoutRules`                                      | `HomeScreen` grid structure                                                    | **High**. Two ViewModels write this. The bug report (#6) states these options don't work, indicating the value is either not being saved correctly or `HomeViewModel`/`HomeScreen` is not re-rendering based on the updated value.                                              |
| `home pages / tile slots`      | `CaregiverViewModel` (`LayoutPagesScreen`)       | `Room`: `home_tiles` table via `RoomHomeLayoutRepository`                                                | `HomeViewModel`                                                         | `HomeScreen` pager/pages                                                       | **Very High**. Bug #1 (apps on additional pages not visible) points directly to a flaw here. The logic in `HomeLayoutRules.effectivePageCount` and `HomeViewModel`'s pagination calculation is likely incorrect or is not being triggered on data change.                     |
| `selected/allowed apps`        | `CaregiverViewModel`                             | `Room`: `home_tiles` table (as `APP` type tiles)                                                       | `HomeViewModel`                                                         | `HomeScreen` tiles                                                             | **Medium**. This seems tied to the `home pages` issue. If an app is assigned to a tile on a page that isn't visible, the app won't appear. The core issue is likely pagination, not app selection itself.                                                                  |
| `hidden apps`                  | `CaregiverViewModel` (`HiddenAppsScreen`)        | `DataStore`: `hidden_apps.preferences_pb` via `DataStoreHiddenAppRepository`                             | `AppListViewModel`                                                      | `AppListScreen` (the "All Apps" view)                                          | **Low**. This seems to affect the secondary app list, not the primary home screen. The user-reported bugs are focused on the home screen.                                                                                                                                   |
| `layoutLocked`                 | `GuidedSetupViewModel`, `CaregiverViewModel`     | `DataStore`: `LAYOUT_LOCKED` key                                                                       | `HomeViewModel`, `CaregiverViewModel`                                   | `HomeScreen` (for edit behavior), also incorrectly on every tile               | **High**. The primary bug (#2) is about rendering (the lock icon on each tile), which is a UI-level mistake in `HomeScreen`. The dual-write from two ViewModels is also a risk for state inconsistency.                                                                     |
| `caregiverPinHash / pinConfigured` | `GuidedSetupViewModel`, `CaregiverViewModel`     | `DataStore`: `PIN_HASH_HEX`, `PIN_SALT_HEX` keys                                                       | `HomeViewModel` (for 5-tap), `CaregiverViewModel` (for verification)    | `PinEntryScreen`                                                               | **Very High**. Bug #3 (5-tap fails if PIN not set) indicates `HomeViewModel`'s `onClockTappedCaregiverAccess` logic doesn't correctly handle the null/empty PIN case. It likely assumes a PIN always exists and tries to verify, instead of routing to the creation flow. |
| `onboardingCompleted`          | `AppViewModel`, `GuidedSetupViewModel`           | `DataStore`: `ONBOARDING_COMPLETE` key                                                                 | `EasyUiNavGraph` (for start destination)                                | (Controls navigation flow)                                                     | **Medium**. Multiple writers could cause race conditions, but this is less likely to be the source of the persistent rendering bugs. It's more likely to cause navigation issues on the first run.                                                                            |
| `emergencyContact(s)`          | `GuidedSetupViewModel`, `CaregiverViewModel`     | `DataStore`: `EMERGENCY_PHONE_NUMBER`, `EMERGENCY_NUMBERS` keys                                          | `HomeViewModel`                                                         | `HomeScreen` (Emergency tile)                                                  | **High**. Bug #8 (contacts not showing) suggests `HomeScreen` isn't reading the number from `HomeViewModel`'s state, or the `ViewModel` isn't loading it correctly. The dual-write locations add risk.                                                                         |
| `directCallShortcut(s)`        | `CaregiverViewModel` (`FavoriteContactsScreen`)  | `Room`: `home_tiles` table (as `CONTACT` type tiles)                                                   | `HomeViewModel`                                                         | `HomeScreen` (as contact tiles)                                                | **High**. This shares a similar risk profile with emergency contacts and app pages. The data is likely being written to the database, but `HomeViewModel` or `HomeScreen` is failing to read or render the corresponding tiles correctly. This is part of bug #8.              |
